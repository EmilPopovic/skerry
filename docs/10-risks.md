# Risks

Ordered by expected cost. Each carries a mitigation that is scheduled, not hoped for.

| Risk | Severity | Mitigation |
| --- | --- | --- |
| **Owning the Wayland/X11 platform layer is a large, unglamorous surface** — six weeks before anything is visible, and a long tail of compositor quirks | High, and **now measured** | [Spike D](../spikes/d-platform-and-dnd/README.md) de-risked the hardest parts and the decision held: we are a drag source against GTK 4 and Qt 6 on both display servers, with files landing on disk. `winit` reaches 5 of 9 capabilities and has no `start_drag` at all, so the reversal trigger in [ADR 0002](adr/0002-own-platform-layer.md) is answered rather than pending. What the spike *did* find is that the long tail is real and silent — see the three rows below. |
| **Wayland drag-and-drop and clipboard gaps across compositors** | High | Spike D covered wlroots (Hyprland 0.53.3) and found three gaps there alone; GNOME and KDE runs are owed. Keep the X11 path working. Document per-compositor failures rather than pretending they do not exist — which now means three documented rows instead of one hoped-for mitigation. |
| **Three drag-and-drop and clipboard failures report nothing at all** | High | A discarded primary selection, an unreported drag action, and an undelivered `dnd_finished`, all measured on Hyprland 0.53.3 and all producing no protocol error. `sk-plat` cannot detect any of them, so the mitigation is a design rule: treat every unconfirmed drop as a copy, never make a feature depend on the primary selection, and never implement move as copy-then-delete driven by `dnd_finished`. The last one is the dangerous one — it deletes user data on the wrong branch either way. |
| **The X11-to-Wayland clipboard bridge is broken on at least one shipping compositor** | Medium | On Hyprland 0.53.3 a selection does not cross the boundary in either direction, and a GTK client fails identically, which places the failure outside our code. Our own ICCCM path is verified both ways against GTK, including a 1.36 MB `INCR` transfer. Nothing can be done from inside a client; the mitigation is that Skerry is a native Wayland application, so the common case does not use the bridge. |
| **The X11 and Wayland drag-action vocabularies cannot be unified** | Medium | XDND has copy, move, link, ask and private; `wl_data_device_manager.dnd_action` has copy, move and ask and no link. `sk-plat` exposes the union and the policy above it greys out what the current display server cannot express. A "link here" entry on Wayland has to be built from `ask` plus a menu of ours. |
| **A custom renderer means no toolkit accessibility** | High | **Built, and not with `accesskit`**: its Unix adapter is `zbus` and an async executor, which [ADR 0005](adr/0005-no-async-runtime.md) forbids and [ADR 0023](adr/0023-d-bus-is-a-socket-we-speak-ourselves.md) already declined once. `sk_desktop::atspi` speaks AT-SPI on the bus we write ourselves, from a tree `sk_app::a11y` derives from what the frame recorded so it cannot drift — [ADR 0026](adr/0026-at-spi-is-a-tree-we-publish-on-the-bus-we-already-speak.md). `a-screen-reader-can-read-the-window` walks the published tree with `gdbus`, which is somebody else's client. What is **not** done is a pass with Orca itself over a real task, which is that ADR's revisit trigger. |
| **GPU driver variance, and virtual machines with software rendering** | High | The GL fallback is tested on llvmpipe on *every* CI run — llvmpipe is the CI baseline, not an afterthought. A CPU raster path only if Spike A shows it is needed. |
| **Scope creep from Total Commander expectations** | Medium | [11-non-goals.md](11-non-goals.md) is enforced in review. A feature that does not serve one of the ten rules waits for 1.1. |
| **Fractional-scaling blur — the classic custom-renderer tell** | Medium | Handled in Spike A, and then found to be blurry anyway: the per-glyph assertion reported 0 of 29.6 M quads scaled while the compositor stretched the whole surface. Spike D replaced it with a framebuffer test that locates itself — the longest run of one-physical-pixel alternation in the compositor's own capture, 64 px of 64 expected. Both checks belong in CI; neither subsumes the other. |
| **Text edge cases: RTL, CJK, combining marks, 255-byte names, invalid UTF-8** | Medium | `swash` from the first commit, and an adversarial-filename fixture directory that every renderer change runs against. This is the defect we are explicitly not inheriting from the prior art. |
| **One-developer bus factor against a large surface** | Medium | Crate seams chosen so `sk-preview`, `sk-desktop` and `sk-index` are contributable without understanding the frame loop. The layering check keeps that true under pressure. |
| **`wgpu`'s dependency weight versus rule 10** | Medium | A hard number in the budget table and a `Renderer` seam that makes an `ash` backend a contained swap. [ADR 0003](adr/0003-wgpu-first-backend.md) names the triggers instead of leaving it to taste. |
| **Distro-agnostic claims decaying into "works on the maintainer's distro"** | Medium | The forced-degradation matrix (`SKERRY_DISABLE=…`) runs in CI, and both architectures are built from the first commit. Portability is a test, not a promise. |
| **The operation engine losing data** | Low probability, unbounded cost, and **four defects already found** | M3 is gated on [Spike E](../spikes/e-operations/README.md)'s matrix being green in CI, and the matrix now exists: 46 checks, one binary, no arguments, discovering which filesystems to test. It found `copy_file_range` turning a 1 GiB sparse file into a gigabyte of zeros, `RENAME_NOREPLACE` refused by ntfs-3g so that *nothing* copied to an external drive, an ignored `unlink` that left a temporary file linked into a hardlink set, and a file-type test that walked a directory as a file. Two of the four pass a byte-for-byte comparison. Every destructive path routes through trash by default; a cross-filesystem move verifies the destination before unlinking the source. |
| **A destination filesystem that cannot hold what the source has** | Medium | NTFS refuses a filename that is not valid UTF-8, has no POSIX mode bits, rounds timestamps by 89 ns and takes no extended attributes — and it is what an external drive is formatted as. `sk-fs` distinguishes *not preserved* from *not preservable* with a runtime probe rather than a list of filesystem names, and reports what it could not keep instead of claiming success. Measured in [Spike E](../spikes/e-operations/README.md#per-filesystem). |
| **The 1M-entry working set sits on a cache cliff** | High | 28 MB of names fits a laptop's L3 and not a Pi's, and two four-core machines measured **22× apart on random reads** and 4.5× apart on the same sort. [Spike F](../spikes/f-index-and-search/README.md#isolating-it-four-cores-with-cache-four-cores-without) established that the variable is cache, not cores. Mitigation is a design rule rather than a test: prefer sequential passes over a compact representation to indirection, because the indirection is what the slow machine cannot afford. |
| **The inotify watch budget is per-user, shared, and not a constant** | High | 60,793–65,536 depending on the machine's memory, and **one million-file tree costs 34% of it**. A file manager gets what is left after the IDE, the sync client and the language server, and learns the remainder by being refused one directory at a time. [Spike C](../spikes/c-watching/README.md) measured it; `ENOSPC` needs a real policy, because the failure it prevents is a listing that looks current and is not. |
| **A single directory with a million entries is a different problem from a million-file tree** | Medium | 8.4× the walk time, because a directory is the unit of parallel work and there is only one of them. Its name stream cannot be split — `getdents64` cookies are discoverable only by reading forward — so `sk-fs` needs a second strategy, deferring `statx` to the pool, and a per-directory choice between them. Measured in [Spike F](../spikes/f-index-and-search/README.md#making-the-flat-directory-work). |
| **Sorting a million filenames misses its budget on reference hardware** | Medium | 191 ms against a 120 ms target after nine implementations, down from 948 ms. Inside the 300 ms hard fail and recorded as unmet rather than widened. An MSD radix over collation keys is now implemented and measured: 1,460 → 166 ms at 973,759 entries on a laptop, still 1.4× over target. The remaining route is threaded buckets, which Spike F measured at 3× on a laptop. |
| **Benchmarks that measure the machine's other work** | Medium | Load contamination cost a 6.6× error before it was caught. Every sweep waits for a one-minute load average under 1.3 and records the load beside the result — [12-measurement.md](12-measurement.md) is the policy, and it exists because this was learned the expensive way. |
| **Theming expectations — users will ask for their GTK theme** | Low | Ship a strong opinionated default, read the system light/dark preference and accent colour through the settings portal, offer a colour-scheme file. Say no to toolkit theme matching, in the README, once. |
